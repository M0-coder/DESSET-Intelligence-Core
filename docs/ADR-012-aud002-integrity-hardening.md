# ADR-012 — INT-012.1: integridad de insumos y clasificación de probes

Base auditada: PR #27, e9a1196bf7f756fe6c2781feb94ab7f643259eba. [AUD-002 #28](https://github.com/M0-coder/DESSET-Intelligence-Core/issues/28). Sin autorización de merge o producción.

## Contratos corregidos

- F01: `--output` debe ser una ruta nueva, fuera del staging declarado y sin nombre de PBF/OSRM. Se resuelve el directorio padre antes de consultas. Se escribe JSON completo a archivo temporal privado, se sincroniza y se publica mediante enlace duro exclusivo; no se reemplazan destinos existentes, incluso si aparecen entre preflight y publicación. Un error de I/O es fallo, nunca éxito. El entorno presupone directorios controlados por el operador, no un adversario que renombre directorios concurrentemente. El filesystem debe soportar enlaces duros; en caso contrario, fail closed.
- F04: exigir conjunto mínimo de archivos del perfil MLD predeterminado de OSRM v6.0.0 (sin afirmar compatibilidad universal de otras versiones). Fuente: [storage_config.hpp](https://github.com/Project-OSRM/osrm-backend/blob/v6.0.0/include/storage/storage_config.hpp), [storage.cpp](https://github.com/Project-OSRM/osrm-backend/blob/v6.0.0/src/storage/storage.cpp). Las cuatro estructuras MLD y los índices espaciales/propiedades no pueden estar vacíos. Los artefactos opcionales o de contenido potencialmente vacío no se rechazan por longitud cero solamente. Un inventario coherente con archivos sintéticos no demuestra grafo binario válido. `graph_readiness_control_result=NOT_VERIFIED` hasta arranque real; no autentica origen, versión declarada o daemon.
- F05: `route_outcome` diferencia ROUTE, NO_ROUTE (celda null de respuesta validada), INFRA_FAILURE (conexión, timeout, HTTP 408/429/5xx) e INVALID_INPUT_OR_RESPONSE. `expected_outcome` admite ROUTE (valor por defecto para compatibilidad) o NO_ROUTE declarado. No-ruta esperada PASS de la comprobación, no región con ruta viable. No deducir expectativas geográficas de coordenadas aproximadas. Infraestructura fallida tiene prioridad en resultado agregado; `queries_fail` cuenta todos los controles no PASS. Los códigos HTTP no-200 restantes se clasifican como inválidos, no como prueba de no-ruta. Mantener hashes de respuestas aceptadas; fallos antes de respuesta validada no poseen esos hashes.
